# Loop 诊断与修复引擎（模块⑦）

> 吸收：`lingjian-prompt-inspector`（6 段式审查）、`ai-video-storyboard-framework`（continuity ledger + 返工规则）、`seedance-compliance-director`（IP 规避）。
> 核心哲学：**哪里错修哪，正确的不重来。**

---

## A. 6 段式审查（逐段输出思考+问题+确信度）

| 段 | 检查项 | 关键规则 |
|---|---|---|
| 1 风格 | 风格定义是否稳定 | 风格前缀须堆实（光影+"年度票房冠军定位"类实战词），不轻易改措辞 |
| 2 角色 | 角色是否清晰定义 | 有参考图/主要视点/明确外貌者须单独命名；后续一律用名不用"白衣女子"；同屏分身用"mika分身1" |
| 3 场景 | 场景划分是否正确 | 按背景显著变化切分；同地点换角度不算切换；光线剧变算新场景 |
| 4 参考一致 | 参考图编号是否对得上 | 提示词提了但没给图→警告；给了但没用→警告 |
| 5 参考分类 | 帧/角色/场景参考图混入风险 | 角色参考图背景混入、动作混入→警告；场景参考图优先用文字 |
| 6 镜头 | 运镜/时长/逻辑 | 自动分镜补"电影级分镜"；手动分镜须指定运动后画面变化；不轻易改作者时间点 |

### 问题表格式
| 检查段 | 问题类型 | 具体问题 | 严重程度 |
|---|---|---|---|
| 2-角色 | 命名不规范 | 用"girl"作角色名 | 警告 |
| 3-场景 | 划分缺失 | 光线剧变未定义新场景 | 错误 |

严重程度：🔴错误（必修）/ 🟡警告（建议修）/ 🟢提示（可优化）。

## B. 返工规则（铁律）
- **失败要诊断，不要重抽**：定位问题镜 → 只修该镜 → 复检 → 不重跑正确镜。
- ledger.md 每镜记录诊断结果与修复动作，向上追溯资产版本。

---

## C. IP / 合规规避（seedance-compliance-director 精华）
- **连字误杀**："仓库里"→"仓库内"（避"库里"）；"迪X尼"→重写。
- **隐性 IP 打散**：奇幻森林→"发光巨型植物森林"；名作场景→重构视觉元素。
- **双关拆解**：敏感双关拆成中性描述。
- Common IP Replacements 表按项目维护。

## D. 新增自检（机制5 — 治"下游又把已定稿资产重新描写一遍导致前后矛盾"）

> 在⑤分镜清单 / ⑥视频提示词生成后**自动跑**，不依赖人工。这是你之前翻车的兜底网。

**扫描对象（仅「镜头语言区」）**：本镜提示词中是否出现——场景视觉描写、人物外貌描写、道具外观描写。引用区（从 bible 原样粘贴的锁定块）**不参与扫描**，因为那本就是真相源。

**判定逻辑**：
1. 提取 bible.md 已登记资产：SCENE-* 锁定块（结构/光照/色彩）、CHAR-* 锁定事实块（外貌/服装/状态）、PROP-* 锁定块（外观）。
2. 若「镜头语言区」出现以下任一情况 → 即「AI 擅自重写已定稿资产」，判失败：
   - **重描写场景**（"昏暗的客厅""old house"类自由描述，而非 `SCENE-0X` 引用）→ 🔴失败
   - **重描写外貌**（"a beautiful woman""中年男人"未绑定 CHAR-* 引用）→ 🔴失败
   - **重描写道具**（未绑 PROP-* 的外观描写）→ 🟡警告
3. 命中即打回，要求把描写删掉、改为引用区 `SCENE-0X`/`CHAR-0X`/`PROP-0X` 后重出。

**为什么这样治你的坑**：之前前后矛盾 = ③/④定稿一份描写、⑤/⑥ AI 又写了一遍、两遍对不上。本自检确保⑤/⑥阶段**根本没有撰写描写的权限**，描写 100% 来自引用区，自然不可能出现"两遍对不上"。

**自检输出模板**：
```
[新增自检] 镜号 SHOT-0X
- 引用区资产：SCENE-01 ✅ / CHAR-01 ✅ / PROP-01 ✅
- 镜头语言区扫描：无重描写 ✅ / [列出命中项：如"出现'昏暗客厅'自由描写"]
- 结论：通过 ✅ / 失败打回 🔴（原因：镜头语言区出现未授权重描写，须改用引用区）
```
